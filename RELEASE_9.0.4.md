# Somata 9.0.4 — статическая анимация, настройки, GPU Fill / Spiral

Основа: Somata 9.0.3. Сохранены исходные 23 стандартных проекта и 10 сцен COSMIC ODYSSEY (их геометрия, музыка, цвета и эффекты не изменены). Менялись только настройка видимости меню в двух версиях авторского плейлиста.

## Настройки по умолчанию

- ☑ Отображать FPS; ограничение FPS 60.
- ☐ Автоматически показывать консоль при ошибке.
- ☐ Отображать пресеты.
- ☑ Отображать проекты.
- ☐ Отображать морфинги.
- ☐ Отображать профили.
- ☐ Пробел ставит морфинг на паузу.

Ключ сохранения видимости заголовка обновлён, чтобы старая настройка 9.0.3 не перекрыла новые дефолты. Последующие действия пользователя сохраняются. Отдельные пользовательские плейлисты могут содержать свои настройки меню.

## Анимация параметров

- «Анимация» не запускает самостоятельное движение: только один конечный переход после редактирования параметра.
- Добавлены те же **названия режимов**, что в Blue: Топологический, Спокойный, По окружности, Fade, Слайдшоу. Тип слайдинга: Минимальный поворот / Секторный / По фазе. Выбор передаётся прямо в общий Blue geometry executor, а не считывается случайно из активного Blue-профиля.
- Для обычной геометрии используются общие Blue geometry executors (`blue-anchor-linear`, `blue-circle-slide`, `blue-fade`), а не отдельный контур. Статические конечные геометрии кэшируются на всю продолжительность tween.
- Для strict Spiral числовые параметры меняются на точной статической геометрии. **При структурных изменениях**, пока отдельный retained GPU edit-pair не реализован, вместо резкого скачка выполняется затухание исходной exact Spiral до нуля и появление конечной exact Spiral. Это **не то же самое**, что настоящий Blue Topology/Phase для Spiral. Для Слайдшоу статическая смена формы пока также использует endpoint Fade, а не полный Blue Light runtime. Эти ограничения не должны маскироваться тестами.

## GPU Fill / FPS-консоль

- Исправлена ошибочная самоперерисовка GPU-only Fill при устойчивой неготовности backend. Ветви ordered-fill и обычного GPU Fill больше не требуют следующего кадра **только из-за собственного FAIL**. Настоящие события warmup/ready и любые живые параметры/анимации продолжают инициировать кадры.
- `console.warn('[SpiroStar Fill] NOT DRAWN…')` теперь появляется во встроенной FPS-консоли. `[Somata Performance]` отображается не чаще одного раза за 3 секунды, чтобы не добавлять нагрузку при лагах.
- Смена ярлыка логов GPU с исторического `Somata 7.11.16` на `Somata 9.0.4`. GPU ID и данные ошибки сохраняются.
- **Наличие `GPU Fill backends returned false` само по себе не устранено.** Программа продолжает сообщать об отказе backend и может пропустить Fill, когда точный GPU carrier недоступен. Нет тайного Canvas fallback для strict Spiral.
- Тяжёлые сцены «04 INFINITE HELIX» и «7 Бесконечная спираль» содержат 3 слоя с активным Morph/Corridor. Удаление повторных GPU Fill repaint и кэширование статических endpoint-геометрий не доказывают устранение GPU stalls на NVIDIA; для этого требуется аппаратная проверка.

## Тесты

- `tests/v904-settings-fill-diagnostics-regression.js`: реальные UI defaults, оба формата логов в FPS-консоли, сохранность плейлистов, отсутствие рекурсивного redraw в ветке Fill `resolve()`.
- `tests/v904-static-animation-blue-types-regression.js`: пять UI-режимов, реальные Blue geometry plans, однократная подготовка endpoint-геометрий, конечность перехода.
- `tests/v904-strict-spiral-static-edit-regression.js`: при изменении N исходная strict Spiral затухает и новая появляется через нулевую непрозрачность; без неавторитетного CPU Morph.
- Общий тестовый pipeline остался доступен: `node tests/run-all.js` и `node tests/run-extended.js`.

### Ограничения проверки

Тесты Chromium без физической NVIDIA WebGPU не измеряют FPS на устройстве пользователя и не удостоверяют итоговые GPU-пиксели. Если программа продолжает сообщать `GPU Fill backends returned false`, необходимо изучить `fillStatus`, `fillContract`, `fillRuntime`, WebGPU generation и состояние GPU Hub из раскрытого объекта ошибки. Эти данные нужны, чтобы чинить конкретный отказ backend, а не выключать диагностику.
