# Somata 16.3 GPU Fourier Corridor

База: 16.2 GPU Fourier. Изменения не касаются скелета, формул порядка, фазы морфинга, исходной окружности, формата проекта и правил преобразования копий Коридора.

## Новый маршрут

`Skeleton → Order → Profile source → CPU resampling (96) → GPU Fourier (288) → resident master → indexed GPU Corridor copies → WebGPU`.

`recordGpuFourierCommands(frameCtx, true)` записывает геометрию один раз без копий, во временном приватном дескрипторе. Прозрачность мастера нормализуется и восстанавливается через finally; цвет и непрозрачность экземпляра задаёт существующий Corridor copy store. При feature-scoped Base используется исходный владелец кадра, чтобы не потерять данные других эффектов или дважды умножить базовую прозрачность. Дескриптор не попадает в CPU FrameContour, обычный кэш мастера или потребители CPU-координат.

`gpu-dispatch.js` пробует новый маршрут до построения прежнего CPU-мастера; `geometry-scene-routing.js` поддерживает также существующий отложенный Layer Scene. `stroke-renderer.js` передаёт тот же командный энкодер из Fourier compute в indexed Corridor draw. Число вычислительных групп определяется числом независимых ветвей мастер-формы, а не числом копий. Поворот, масштаб, прозрачность и цвет экземпляров обрабатываются прежним GPU-инстансером. Дополнительной передачи GPU→CPU в рабочем маршруте нет.

## Длина дискретизированной дуги

Четвёртая компонента существующего `vec4<f32>` в resident Fourier buffer теперь хранит накопленную длину вдоль восстановленной ломаной в координатах мастера:

- `xy` — положение после нормализации и преобразования мастера;
- `z` — относительная толщина;
- `w` — накопленная длина, первая точка каждой ветви имеет w=0.

Для замкнутой ветви полная длина = last.w + distance(last.xy, first.xy). Замыкающий сегмент представлен отдельно в топологии. Для экземпляра Коридора длины умножаются на абсолютный масштаб копии. Это длина дискретизированной кривой, не точная аналитическая длина Фурье или сплайна. Вычисление выполняется после преобразования координат, внутри того же workgroup, без дополнительного буфера. Индексный рендерер линии читает xy и z; поле w подготовлено для будущих потребителей. Это ещё не публичный универсальный VisualCarrier и не перевод эффектов на GPU.

## Границы и резервный маршрут

Фурье 10–200%, округлые стыки и концы, только Base/Line без других потребителей. Статические контуры и допустимые основные провайдеры Blue/manual могут использовать маршрут, если записывают неготовый Fourier-дескриптор. Переходы, уже материализовавшие CPU-контур, split-спирали, смешанный CPU/GPU Коридор (сдвиг цвета и задержка палитры), заливка, лампы, Web, Граффити, Glow, Outline, прочие эффекты, ошибки записи и непрогретые GPU-конвейеры остаются на прежнем маршруте. Независимые Orange/Green/Lightning не изменялись. Ресемплинг, подготовка графа и индексов пока CPU. При скруглении 0–<10% оставлен точный CPU-алгоритм. Новые буферы по-прежнему выделяются на batch; постоянное переиспользование ресурсов и FPS — отдельная работа.

## Диагностика

В консоли после изменения параметров совместимого слоя с включённым Коридором:

```js
__somataGpuFourierStatus().corridor
```

`lastReason: 'resident-master-compute'` означает, что маршрут принят/закодирован (не доказательство исполнения GPU). `attempts`, `encoded`, `fallback`, `lastReason` — отдельные счётчики Коридора. При отказе новый дескриптор не передаётся старому рендереру: прежний мастер записывается самостоятельно. `lastDecision.reason: 'corridor-dispatch'` в обычной диагностике означает делегирование выбора Коридору.

Сравнить с предыдущим алгоритмом: `window.__somataGpuFourierEnabled = false` и обновить кадр; вернуть `true` и обновить кадр. Страница `http://localhost:8000/app/tools/gpu-fourier-check.html` сравнивает реальный WGSL с 14 CPU-эталонами и дополнительно проверяет накопленные длины, монотонность и независимость начальной точки каждой ветви. Только диагностическая страница использует readback.

## Проверки

130/130 Node-тестов: 127 исходных, 3 новых. Новые проверки охватывают допуск и отказ, изолированные feature-scoped планы, реальную запись статического многоугольника и спиралей ±1 с восстановлением alpha, и подключение вычислительного энкодера к индексному рендереру Коридора и префикса длины в исходнике WGSL. Это не исполнение WGSL. Попытка открыть диагностическую страницу Chromium заблокирована политикой среды (`ERR_BLOCKED_BY_ADMINISTRATOR`). Фактическая компиляция GPU, визуальный результат и FPS не проверены.
