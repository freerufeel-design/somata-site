# Somata 16.4.2r — Lamp Controls & Stable Motion

**16.4.2r:** Master: ламповые поля записываются адресно, запасное определение пути берётся из реестра. Новые лампы: яркость 100%, радиус 30×2, мягкость 100×1, ключевой режим и прилипание. Адаптация цветомузыки выключена по умолчанию. Стабильный режим использует линейные часы Blue для ключевых траекторий многоугольников, с перепараметризацией полярного движения по длине. Деформация линии, прилипание и специальные GPU-спирали не гарантируют постоянную экранную скорость.

# Somata 16.4.2q — Responsive Morph Header

**16.4.2q:** Шапка Blue объединяет период и три селектора в адаптивную строку; группы переносятся по доступной ширине. Стрелки и прежние обработчики сохранены. Строка профиля также переносится без наложения. Только интерфейс.

# Somata 16.4.2p Adaptive Exponent Multiplier

**16.4.2p:** Множитель экспоненциальности адаптивной подсветки ×3 по умолчанию, ×1 возвращает прежний отклик, ×0 — линейный. Умножается итоговая степень с учётом авто-экспоненты, не яркость. Нулевое значение ползунка без авто-экспоненты остаётся линейным. Множитель сохраняется в проекте и доступен в маршрутизации.

**16.4.2o:** Для «Ведьминского» и «Морских водорослей» Коридор использует непрерывную виртуальную опору единичного масштаба вместо мгновенной смены ближайшей копии. При схлопывании вклад опорных копий передаётся плавно. Для переходов с одной орбитой и минимум тремя вершинами на обоих концах сохраняется авторское начало и направление обхода; затухание коротких рёбер согласовано с координатами витка, шириной и округлённым конечным контуром. Другие режимы построения, методы скругления и формулы масок не изменены. Проверка 240 смен опоры и 160 стыков фаз (дискретизация кривых Безье) в Node; визуальный WebGPU-прогон не проводился. Переходы с изменением количества орбит, с двумя вершинами и за пределами специального диапазона порядков не покрыты этой проверкой соответствия.

# Somata 16.4.2n Spiral Ribbon Masks

**16.4.2n:** «Рубленый» переименован в «С наслоением» (старый ключ `chopped`); «Математический» из 16.4.2m сохранён без изменения маски как «Цветочек» (старый ключ `mathematical`). Новый «Математический» (`bandXor`) использует те же парные полосы, что «С наслоением», но с чётностью наложений. В Коридоре полосы строятся из фактически соединяемых концов ветвей текущей линии; радиальных замыканий к фокусу в двух новых режимах нет. Несовпавшие продолжения не соединяются искусственной длинной перемычкой. Вырожденная коллинеарная пара пропускается; нечётная непарная ветвь остаётся свободной. «С наслоением» объединяет покрытие полос с одной прозрачностью; для нескольких полос CPU нормализует их покрытие до положительного winding. Новый «Математический» использует stencil parity исходных замкнутых полос, включая самопересечения. Настройки окна фаз и защитный fallback затухания сохранены. Упрощение границы 0,2 экранного пикселя; при разрыве ветвей остаются концевые замыкания, а не продолжение через отсутствующую геометрию. WebGPU в браузере и реальный FPS не проверены; тесты проверяют команды маски и их CPU-растеризацию, а не конечный GPU-кадр.

**16.4.2m:** Коридор по умолчанию не добавляет вращение от движения копий обычной спирали. Относительный угловой шаг витков сохраняется, прежний режим доступен галочкой «Вращение спирали при движении». Специальные маршруты разворачивания сохраняют свои правила. Новый Orange создаётся без обычных и специальных строк; существующие профили не меняются. При создании пустого профиля работающий Orange останавливается без автоматического повторного запуска.

**16.4.2l (Spiral Mask Fill):** Режим «Межвитковый» удалён из меню; старые проекты переходят на «Рубленый». Рубленый использует радиальную развёртку текущих линий, объединяя полосы между соседними пересечениями (пары снаружи внутрь; нечётный внутренний остаток не закрашивается). Границы упрощаются с допуском 0,2 экранного пикселя. Для одиночной геометрии без общих радиальных интервалов — проверенные локальные полосы. Математический использует XOR масок, открытые ветви замыкаются к фокусу (начало координат слоя). При известных идентификаторах источника/цели плавность следует окну профиля; иначе используется защитное симметричное затухание на стыке. Для Коридора копии объединены в одно stencil-поле (индивидуальный цвет/alpha копии не применяется; учитывается порог видимости). Node проверяет геометрию и правило чётности, но не растеризацию GPU; FPS требуется проверять в браузере.

**Настройки окна фазы:** переходы цвета и прозрачности обычной заливки Blue используют окно «Смена режима» профиля. Слияние/разделение орбит и оба режима заливки спирали используют ту же долю фазы вместо фиксированных 25% и 12%. Для единой сетки спирали без идентификаторов старой/новой области требуется общее погашение на стыке: при выборе начала или конца фазы оба плеча используют заданную долю, не более 50% на каждое; «Вся фаза» — половина фазы на каждое плечо; 0% — мгновенная смена. Это временный симметричный режим, а не раздельная смена отдельных областей. Геометрия и ограничения границ 16.4.2k сохранены.

**16.4.2k:** заливка спирали использует ветви текущего маршрута линии; межвитковые ячейки с пересечениями видимых ветвей отбрасываются, покрытие объединяется по winding. Для межвитковой заливки активного Blue с динамической геометрией введено затухание в последних 12% и нарастание в первых 12% линейной фазы (в каждой фазе, даже при неизменной топологии). Линия не гаснет. Если безопасных ячеек не найдено, межвитковая заливка не подменяется полосой: в отдельных статических конфигурациях Local/Classic может отсутствовать. Проверка пересечений выполняется по дискретизированным линиям и имеет ограничение числа проверок. Градиент не реализован. Проверки Node не заменяют визуальный прогон WebGPU.

**16.4.2j:** в FPS-консоли добавлена выключенная по умолчанию галочка «Ручные изменения». Геометрические события с подтверждённым ручным вводом или связанной пересборкой скрыты из видимого журнала, но сохранены отдельно и в полном отчёте монитора. Автоматические ошибки и естественные стыки фаз не фильтруются. Для событий внутри фазы используется диагностическое окно 250 мс.

**16.4.2i:** синхронизированная длительность редактируется в Geometry; AUTO отображается при TAP-синхронизации. Сброс профиля задаёт прямую линию как цель следующей полной фазы Blue, не обрывая текущую. Ручное изменение синхронизированной длительности отключает TAP для Blue аналогично меню Морфа и сохраняет текущий прогресс фазы.

**16.4.2h:** монорадиус включён по умолчанию в новых проектах и слоях. Явные настройки загруженных проектов и прежняя политика для файлов без `roundingMode` сохранены. Геометрия и монитор не изменены.

## Запуск

Нужен браузер с поддержкой WebGPU.

- **На хостинге** — просто выложить папку: всё работает как есть.
- **Локально в Windows** — двойной клик по `Somata_Start`. Он запускает маленький сервер на встроенном в Windows PowerShell (`serve.ps1`, ничего устанавливать не нужно) и открывает `http://localhost:8000`. Окно консоли держите открытым, пока работаете; закрыли — сервер остановился. При первом запуске из скачанного архива Windows может спросить разрешение («Подробнее» → «Выполнить в любом случае»).
- **Локально в macOS / Linux** — `app/start.command` или `python3 app/serve.py`.

Почему не двойным кликом по `index.html`: код приложения — ES-модули, а браузеры не загружают модули со страниц, открытых с диска (`file://`). По той же причине не подходит обычный `python -m http.server` на Windows — он отдаёт `.js` с неверным типом. Если страницу открыть так, она покажет подсказку. «Файл → Открыть плейлист» работает как раньше.

## Что изменилось по сравнению с 15

Алгоритмы, интерфейс, формат проектов и `default.plist` не менялись. Перестроен код:

- 138 скриптов с общей глобальной областью заменены ES-модулями с явными импортами; точка входа — `js/main.js`.
- Три монолита (`ui-project-runtime.js`, `geometry-gpu-core.js`, `lamp-audio-core.js` — около 70 тысяч строк вместе) разрезаны на 97 модулей по доменам: `geometry/`, `geometry/spiral/`, `corridor/`, `lamps/`, `effects/`, `audio/`, `project/`, `ui/`, `gpu/`, `render/`, `morph-runtime/blue/`.
- Весь код отформатирован (Prettier): ручная «минификация» в строки по 12 тысяч символов развёрнута.
- Строгий режим везде; найденные неявные глобальные переменные объявлены.
- 653 пустых `catch` больше не теряют ошибки: они считаются в `core/suppressed-errors.js` и выводятся в консоль с `?debugErrors`.
- 387 проверок `typeof f === 'function'` для функций, которые теперь всегда импортированы, убраны.
- Номера версий убраны из имён (`lampV261…`, `v286…`, `…V505…`); `app/test-morph.js` переименован в `morph-runtime/manual-morph.js` — это контроллер ручного морфа, а не тест.
- Тесты больше не вырезают функции из файлов по отступам: они берут их по имени (AST) или загружают всё приложение в Node. Добавлен эталонный тест геометрии против исходной 15.

Исправленные баги и оставшийся технический долг описаны в [Карте кода](docs/Code_Map.md#исправленные-баги).

- 3354 вызова `buildOrbitPolylines` в Chrome (сетка из 3024 комбинаций и все слои 22 проектов на четырёх порядках) совпадают с исходной 15 побитово.

Из остальных пяти два нестабильны и в самой исходной версии (повторный прогон оригинала даёт другой кадр). - Загрузка: около 2,1 с против 2,0 с у исходной версии на локальном сервере (234 JS-запроса вместо 138).
