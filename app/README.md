# Somata 16.0 (модульная сборка)

Браузерная среда для многослойной процедурной графики, морфинга и аудиореактивных композиций.

**Документация:** [Суть проекта](docs/Somata_15_Project_Essence.md) · [Карта кода](docs/Code_Map.md) · [Блок-схема архитектуры](docs/Somata_15_Architecture.svg) · [Диагностика скачков и яркости](docs/Jump_Trace.md).

## Запуск

Нужен браузер с поддержкой WebGPU.

- **На хостинге** — просто выложить папку: всё работает как есть.
- **Локально в Windows** — двойной клик по `Somata_Start`. Он запускает маленький сервер на встроенном в Windows PowerShell (`serve.ps1`, ничего устанавливать не нужно) и открывает `http://localhost:8000`. Окно консоли держите открытым, пока работаете; закрыли — сервер остановился. При первом запуске из скачанного архива Windows может спросить разрешение («Подробнее» → «Выполнить в любом случае»).
- **Локально в macOS / Linux** — `app/start.command` или `python3 app/serve.py`.

Почему не двойным кликом по `index.html`: код приложения — ES-модули, а браузеры не загружают модули со страниц, открытых с диска (`file://`). По той же причине не подходит обычный `python -m http.server` на Windows — он отдаёт `.js` с неверным типом. Если страницу открыть так, она покажет подсказку. «Файл → Открыть плейлист» работает как раньше.

## Что изменилось по сравнению с 15

Алгоритмы, интерфейс, формат проектов и `default.plist` не менялись. Перестроен код:

- 138 скриптов с общей глобальной областью заменены ES-модулями с явными импортами; точка входа — `js/main.js`.
- Три монолита (`ui-project-runtime.js`, `geometry-gpu-core.js`, `lamp-audio-core.js` — около 70 тысяч строк вместе) разрезаны на 97 модулей по доменам: `geometry/`, `geometry/spiral/`, `corridor/`, `lamps/`, `effects/`, `audio/`, `project/`, `ui/`, `gpu/`, `render/`, `morph-runtime/blue/`.
- Весь код отформатирован (Prettier): ручная «минификация» в строки по 12 тысяч символов развёрнута.
- Строгий режим везде; найденные неявные глобальные переменные объявлены.
- 653 пустых `catch` больше не теряют ошибки: они считаются в `core/suppressed-errors.js` и выводятся в консоль с `?debugErrors`.
- 387 проверок `typeof f === 'function'` для функций, которые теперь всегда импортированы, убраны.
- Номера версий убраны из имён (`lampV261…`, `v286…`, `…V505…`); `app/test-morph.js` переименован в `morph-runtime/manual-morph.js` — это контроллер ручного морфа, а не тест.
- Тесты больше не вырезают функции из файлов по отступам: они берут их по имени (AST) или загружают всё приложение в Node. Добавлен эталонный тест геометрии против исходной 15.

Исправленные баги и оставшийся технический долг описаны в [Карте кода](docs/Code_Map.md#исправленные-баги).

## Проверки

```sh
npm install        # один раз: acorn для тестов, инструменты разработки
npm test           # все тесты в Node, без браузера
npm run check:graph
npm run lint
node tests/spiral-reference.cjs /путь/к/распакованной/Somata_13.2
```

Браузерные проверки (эталон геометрии и скриншоты всех проектов `default.plist` в WebGPU) — `npm run golden:geometry` и `npm run visual` при запущенном сервере; подробнее в [Карте кода](docs/Code_Map.md#браузерные-инструменты-tools).

## Равенство с 15

- 3354 вызова `buildOrbitPolylines` в Chrome (сетка из 3024 комбинаций и все слои 22 проектов на четырёх порядках) совпадают с исходной 15 побитово.
- `tests/morph-skeleton.test.cjs` выдаёт те же 35 результатов с теми же счётчиками, что исходный тест на исходной 15.
- `tests/spiral-reference.cjs` против исходной 15: 900 случаев, погрешность 0.
- Скриншоты 22 проектов в трёх моментах времени (69 кадров, WebGPU через SwiftShader): 64 кадра совпадают до пикселя с прогоном исходной версии. Из остальных пяти два нестабильны и в самой исходной версии (повторный прогон оригинала даёт другой кадр). Ещё три зависят от того, успела ли закончиться асинхронная подготовка GPU к моменту снимка: при более долгом ожидании они совпадают до пикселя.
- Загрузка: около 2,1 с против 2,0 с у исходной версии на локальном сервере (234 JS-запроса вместо 138).
