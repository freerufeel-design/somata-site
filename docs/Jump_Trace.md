# Диагностика скачков Somata 15

Встроенный скрипт выключен по умолчанию. В консоли страницы (F12 → Console):

```js
SomataJumpTrace.start({seconds: 30, thresholdPx: 20})
```

Воспроизведите скачок с открытой страницей; полезно записать и несколько нормальных фаз до него. Для одного слоя можно добавить `layer: 0` (индексы с нуля). При необходимости отметьте видимый скачок командой `SomataJumpTrace.mark('разошлись витки')`. Выгрузка JSON (работает и после окончания записи):

```js
SomataJumpTrace.download()
```

В отчёте: скачки формы линии и скелета отдельно от поворота/масштаба экземпляров Коридора, изменение числа путей и сегментов, смена маршрута построения, длинные интервалы между кадрами, номер фазы и порядок. Обычное движение, перепривязка путей без стабильного ID, нормальное отсечение копий и смена топологии тоже могут дать события. Это диагностические признаки, а не доказательства дефекта. Запись не читает GPU-пиксели и не подменяет отсутствующий CPU-контур нулями; `cpu-geometry-proxy` — приближение. Пороги считаются в оценочных CSS-пикселях; если большие копии выходят за экран, оценка может быть завышена. Отчёт хранится локально, ничего не отправляется автоматически.

Дополнительно `thresholdLight: 0.20` задаёт порог скачка яркости (0.20 = 20 пунктов на шкале силы одной лампы). Отчёт различает пик входных команд с учётом наложения (`lamp-raw-brightness-rise`) и пик после сглаживания (`lamp-brightness-rise`), отдельно отмечает появление групп ламп (`lamp-overlap`). Для GPU Arc совпадение проверяется по пути и позиции на нём; между разными путями совпадение GPU-координат не измеряется. Для проблеска фиксируются резкие изменения коэффициентов ядра и ореола (`glint-gain-rise`), но не яркость пикселей на скруглении. Пометьте такой момент через `SomataJumpTrace.mark('яркий угол')`.
