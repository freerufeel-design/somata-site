# Somata 8.20.9 — экранная привязка WebGPU-рефракции и композитный снимок сцены

Дата: 22.10.2026. Основа: чистая распаковка Somata 8.20.8.

## Воспроизводимый дефект

На GPU пользователя в сфере был виден фрагмент фоновой сцены, не совпадающий с находящимися непосредственно за ней яркими контурами. Шейдер компилировался и выводил `WebGPU 3D: ... сцена подключена`, но рефракция брала чужую область Corridor.

Найдены две независимые причины:

1. `opticalUv()` возвращала **абсолютную проекцию** преломлённого луча на виртуальную мировую плоскость `z=-7`. Но входная `sceneTex` уже была готовым *экранным* 2D-изображением; абсолютная проекция не гарантирует совпадения с исходным экранным пикселем.
2. `uploadScene()` брала только один Canvas (`finalGpuCanvas` либо `mainCanvas`). При наличии GPU-проходов на отдельных видимых поверхностях — `pathFxOverlayCanvas`, `graffitiGpuOverlayCanvas`, `particleGpuOverlayCanvas` — часть показанной сцены вообще отсутствовала в оптической текстуре.

## Исправление

- WGSL считает **разницу** `projectToScene(refractedExit) - projectToScene(straightRay)` на одной и той же виртуальной глубине. Смещение применяется относительно `input.clipPosition.xy / u.viewport.xy`, то есть экранного пикселя фрагмента. Максимальное отклонение ограничено по пикселям, чтобы крайние касательные лучи не вытягивали в стекло случайные удалённые элементы. Режим `refraction=0` по-прежнему точно выбирает исходный экранный пиксель. RGB-каналы имеют отдельный индекс преломления, Snell-проходы сохранены.
- Canvas2D-мост собирает **фактически видимые** поверхности по порядку композиции: `sceneBlendCanvas → mainCanvas → finalGpuCanvas → graffitiGpuOverlayCanvas → pathFxOverlayCanvas → particleGpuOverlayCanvas → ambientOverlayCanvas`. Учитывает `display/visibility/opacity`, CSS-позиции и размеры, доступные blend modes; скрытые полотна пропускает. Итоговый снимок целиком загружается в существующую `rgba8unorm` WebGPU-текстуру с правильными `TEXTURE_BINDING | COPY_DST | RENDER_ATTACHMENT`.
- `status().sceneOrigin` содержит все реально нарисованные поверхности. При недоступности какой-то поверхности `status().sceneError` сообщает частичный захват, и UI больше не выдаёт его за идеальную синхронизацию.
- 3D остаётся отдельным WebGPU-слоем. Geometry/Static/Morph/Corridor, авторское состояние и остальные проходы не переписывались.

## Проверки

- **NEW:** `node tests/v8209-optical-screen-parity-multicanvas-regression.js` — PASS: zero-refraction UV точно совпадает с пикселем, для Snell действует относительное экранное смещение, GPU-поверхности комбинируются по видимости и CSS-позициям; выключенный слой исключается при следующем кадре.
- Браузерный захват **реальных пикселей Canvas2D в Chromium** с базовой сценой и отдельным overlay — PASS: `[7,21,29]` на фоне, `[253,20,63]` на базовой фигуре и `[0,247,255]` на наложенной линии. Подтверждены `sceneOrigin=finalGpuCanvas+pathFxOverlayCanvas` и один общий снимок для WebGPU. Это не проверка итоговых WGSL-пикселей.
- Встроенные регрессии 8.20.3–8.20.8, `tests/static-modules.js` и общая матрица параметров прошли. Исторический тест `v8206-glass-sphere-visibility-and-icons` обновлён с проверки координат *одного* Canvas на новую семантику композитного снимка; поведение по умолчанию и интерфейс не изменены.

## Что ещё требует аппаратной проверки

На аппаратном WebGPU (NVIDIA) необходимо сравнить экраны с отключённой фигурой, с `Преломление = 0` и со значением 18–35 при активном Corridor и цветных GPU-only эффектах. При нуле внутри силуэта должны совпадать пространственные позиции контуров; при ненулевом значении контуры должны локально смещаться, оставаясь узнаваемыми и привязанными к тому же месту. Дисперсия должна расходить RGB-каналы этих же контуров, а не создавать случайные цветные линии. Результат на NVIDIA в этой среде не подтверждён.

Ограничение: это всё ещё screen-space approximation; для несферических сеток выход луча вычисляется приближённо. CSS-фоновые изображения проекта, не представленные в Canvas, требуют отдельного общего захвата сцены. Замеры аппаратного FPS до/после не проводились.
