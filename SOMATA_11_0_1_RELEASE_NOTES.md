# Somata 11.0.1 — восстановление основного Morph из 10.4

## Почему вышла новая сборка

В 11.0.0 некоторые пути для трех основных режимов выполняли интерполяцию готовых Bézier-контуров вместо оригинального перемещения опорных точек. Такое движение может привести к правильному кадру в конце, но сильно изменить сам переход. Исправление прежней версии решало проверку последнего кадра и не сохраняло поведение старой 10.4.

**Эталон движения:** исключительно предоставленный пользователем архив `Somata_10.4_spiral_zero_modes_morph_ui.rar`, а не промежуточные сборки 10.4.19.x.

## Что сделано

1. Основные режимы («Топологический», «Спокойный», «По окружности») используют изначальный транспорт опорных точек, включая соответствие углов и длительность фаз. Это подтверждено по 288 контрольным снимкам относительно реально запущенной 10.4. Для нескруглённых контуров 138 командных трасс также совпали с исходником; отличия 6 трасс нулевого кадра плоского сплайна учитываются отдельно.
2. Разделены данные **движения** (парная сетка текущей фазы, наследуемая в следующем цикле) и данные **формы** (реальные пользовательские узлы, сохранённые в слое). Ранее они перезаписывали друг друга.
3. Последний кадр Morph совпадает с отображением целевой статической фигуры, а первый кадр новой фазы — с тем же статическим состоянием. Во время короткого переходного участка около границы используется визуальное смешивание старого служебного контура с целевым каноническим контуром. Это Canvas2D-слой отображения, а не вмешательство в перемещение опорных точек.
4. Отдельный прогресс и построение скруглений, MonoRadius, Spiral и Corridor оставлены из более новой ветки. Новая сборка не вводит искусственный Bézier-морфинг вместо трех исходных режимов.

## Где в коде

- `js/geometry/morph.js`: восстановлен выбор старой функции транспорта для трёх базовых режимов; уточнено использование статического пути в моменты t=0/t=1.
- `js/app/ui-project-runtime.js`: на границе Blue-фазы сохраняется оригинальная парная сетка для следующего перехода; авторские узлы фиксируются отдельно.
- `tests/v1101-104-original-motion-regression.js` и `tests/v1101-104-flat-motion-regression.js`: сравнения с эталоном из архивной 10.4.
- `tests/v1101-canonical-endpoint-pixel-regression.js`: проверка соответствия Static и Morph для разных N/K, режима профиля, MonoRadius и скругления.

## Ограничения

Новые тесты пикселей относятся к **Chromium Canvas2D**. Видеокарта/WebGPU отдельно не проверялась. Внутри короткого оконечного диапазона происходит визуальное смешивание контуров: этот механизм устраняет внезапный скачок, но ещё не является единой геометрической интерполяцией всех типов скруглений. В старом наборе есть проверки исторических транспортных эталонов, не совпадающих с 10.4, поэтому полная зелёная регрессия пока не заявляется.
