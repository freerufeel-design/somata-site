# Somata 8.20.5 — WebGPU 3D / 2D Sprite separation

## Основное изменение

Окно «Череп» содержит переключатель **2D · Sprite / 3D · Оптика**.
При создании нового проекта фигура **выключена**; стартовая выбранная 3D-модель — сфера. Сохранённые настройки старых проектов не перезаписываются. Старые проекты с 2D-стеклом без поля `mode` открываются в `2d/legacy`, без изменения художественного вида.

**2D:** PNG/JPEG/WebP/GIF до 3 МБ в отдельном независимом наложении, или прежняя 2D-накладка. Импорт Sprite сохраняется в проектном состоянии. Sprite не выдаётся за оптический 3D.

**3D:** вместо WebGL2 введён самостоятельный **WebGPU** canvas с полигональной сеткой, буфером глубины, перспективой и WGSL-шейдером. Рендер использует общий `WebGPUDeviceHub` Somata. Поддержаны sphere, lens, cube, skull, dodecahedron, cross; старый API `registerMesh()` для пользовательской сетки сохранён.

- Сцена за объектом берётся из текущего 2D compositor canvas как текстура, обновляемая перед каждым GPU кадром.
- Фрагменты сферы вычисляют вход и выход луча по закону Снеллиуса через сферический объём; выход по аналитическому пересечению с задней частью сферы. Три направления преломления для R/G/B создают дисперсию.
- Для остальных многогранников выходная поверхность **пока приближена** толщиной, это не точная многогранная ray tracing модель.
- Фрагмент **замещает** исходный фон рассчитанным преломлённым цветом (alpha 1 внутри фигуры), иначе прозрачное наложение вновь смешивало бы исходный неискажённый фон и скрывало эффект.
- GPU warmup асинхронный, отключённая фигура вообще не запускает 3D-инициализацию. При проблеме WebGPU пользователь видит ошибку; молчаливого Canvas2D fallback в режиме 3D нет.
- Canvas над сценой не зависит от выбранного слоя/Corridor.

## Известные ограничения

Не проверены физические пиксели и производительность на NVIDIA WebGPU: текущая среда позволяет валидировать JavaScript, UI и подготовку GPU-команд, но не гарантирует аппаратный рендер. Компиляция WGSL проверяется асинхронно на реальном устройстве при запуске, с диагностикой ошибок. Для несферических сеток требуется будущий backface/thickness pass для точного направления выхода. Преломление использует снимок плоской 2D-сцены, а не глобальную многократную трассировку лучей; отражения и каустики приближённые.

**Приоритет пользовательской проверки:** 3D → сфера → включить → Corridor + включённое преломление/дисперсия: контуры позади должны изгибаться, а RGB расходиться. Если искажений нет, снять GPU-лог `__somataPrism3DStatus()`.
