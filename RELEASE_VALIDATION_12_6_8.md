# Somata 12.6.8 — Spiral Width Remap Fast Path (экспериментальная)

Дата: 31 октября 2026. База: Somata 12.6.7, включая исправление фазового скачка.

## Что изменилось

В `js/app/geometry-gpu-core.js` две функции, переносящие переменную ширину на Bézier-сегменты после скругления, прежде делали линейный поиск по всему `srcCum` заново для каждого сегмента. На больших недиректных рельсах это означало работу O(sourcePoints × outputCubics). Теперь курсор индекса проходит по монотонным долям и сохраняет историческое условие сравнения границы `srcCum[i+1] < target`, арифметику `target`, интерполяцию и `Math.log/Math.exp` без изменений. При уменьшении доли курсор сбрасывается. Это **не меняет** алгоритм Spline+, фазовые часы, координаты опорных точек, GPU shader, subdivision, порядок витков или передачу 12.6.7.

Основной выигрыш относится к плотным профилям с дополнительными Bézier-сегментами; прямой Spline+ путь уже был быстрым и может не ускориться. Старый 11.0.4 НЕ переносился, поскольку его скругление художественно отличается от утверждённого 12.6.2.

Для аппаратной диагностики добавлена только read-only функция `__somataSpiralPerformanceReport()` в `js/gpu/spiral-bezier-morph-renderer.js`. Она ничего не рендерит и не обращается к GPU для чтения текстуры. После запуска трёх спиралей можно открыть консоль браузера (F12) и выполнить `copy(JSON.stringify(__somataSpiralPerformanceReport(),null,2))`. Результат будет в буфере обмена. Особенно важны `webGpuExposed`, `webGpuHubReady`, `spiralGpuReady`, `spiralGpuFallbacks`, `fpsGovernor`, `topPasses`, `gpuGovernorMs`.

## Зафиксированные проверки

1. `node tests/v1268-spiral-width-remap-regression.js` — точные JSON/FNV-хэши **46 разных конфигураций** Bézier-координат/ширин/маркеров относительно неизменённой 12.6.7. Хэши лежат в `tests/fixtures/v1268-spiral-width-remap-1267.json`.
2. CPU synthetic Chromium (без GPU), 2100 исходных точек, rounded segmented path, 20 замеров и прогрев: 12.6.7 медиана **6,7 мс**, новая сборка медиана **3,0 мс** (отдельные прогоны; мс не FPS).
3. В коротких повторных прогонах 300 точек изменения не дают стабильного ускорения; 900 точек 2,0→1,6 мс. Измерения чувствительны к JIT/GC.
4. Три Spiral слоя с Morph, реальный scheduler в программном Chromium, **стабильный холст 900×600**, GPU принудительно отключён: 11.0.4 — 26,83 и 22,91 FPS, 12.6.7 — 29,68 и 34,03 FPS, 12.6.8 — 39,23 и 26,12 FPS. Две короткие выборки дают большой разброс; **стабильное преимущество полной сцены пока не доказано**. Бенчмарк без CSS был исправлен после обнаружения неверного размера холста. Эти значения не являются аппаратными FPS NVIDIA.

## Доработка целостности модулей

Добавлены безопасные self-registration маркеры для `js/geometry/unified-fillet.js` и `js/geometry/spline-corner-mode.js`; математические тела функций не менялись. В 12.6.7 тесты `static-modules.js` и `browser-preflight.js` были красными из-за отсутствующих маркеров; в 12.6.8 оба проходят. Guard `typeof window !== 'undefined'` сохраняет совместимость с Node.js VM эталонных геометрических тестов. `v1268-spiral-perf-report-regression.js` проверяет read-only диагностический отчёт без WebGPU, без нового кадра и с тремя слоями.

## Ограничения

Ускорение CPU переноса ширины НЕ гарантирует пользовательские 30/60 FPS. Текущий симптом «7 FPS на мощной NVIDIA» требует проверки доступности аппаратного WebGPU и того, какие render passes/драйвер занимают время. Никаких заявлений о полном устранении лагов или визуальной сертификации GPU не делается.
